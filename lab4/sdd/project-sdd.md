## 1. Введение

### 1.1 Назначение документа

Документ описывает **как** устроена система SVS-RVC: её границы, компонентный состав, интерфейсы, сценарии взаимодействия, состояния и зависимости. Аудитория — разработчики, архитектор, тестировщики и сопровождение; SDD служит руководством при реализации MVP и источником трассировки от требований SRS к элементам дизайна.

### 1.2 Область применения

SVS-RVC — Windows-приложение для синтеза вокальной партии по MIDI-партитуре и тексту с переносом тембра RVC. В область проектирования входят импорт MIDI и лирики с привязкой слогов к нотам, выбор и проверка локальных RVC-моделей, офлайн-синтез и перенос тембра, экспорт WAV/FLAC, real-time-мониторинг с задержкой не более 250 мс, локальное хранение проектов, моделей и настроек. Вне области — обучение SVS/RVC-моделей, облачные сервисы, плагин для DAW, лицензирование голосовых моделей, установщик и инфраструктура выпуска.

Проект реализует требования SRS v0.2 [`lab3/srs/srs-svs-rvc.md`](../../lab3/srs/srs-svs-rvc.md) и реестра [`lab3/srs/req-svs-rvc.md`](../../lab3/srs/req-svs-rvc.md).

## 3. Проектные представления

### 3.1 Приоритеты функционала

Приоритеты определены совместно с заказчиком по шкале от 10 (наивысший) до 50 (минимальный).

| Приоритет | Требование | Функциональность |
|-----------|------------|------------------|
| 10 | REQ-FUNC-001, REQ-FUNC-003 | Импорт MIDI и лирики с привязкой слогов; синтез и перенос тембра RVC |
| 20 | REQ-FUNC-004, REQ-FUNC-005, REQ-SEC-001 | Экспорт WAV/FLAC, сохранение в каталог, локальная обработка |
| 30 | REQ-FUNC-002 | Выбор, проверка и управление локальными RVC-моделями |
| 40 | REQ-REL-001 | Надёжный аудиовыход и обработка граничных случаев |
| 50 | REQ-PERF-001 | Real-time-мониторинг с задержкой не более 250 мс |

Приоритет 50 не помещается в MVP при сроке 10 рабочих дней: real-time перенесён в версию 1.1, его архитектура описана в DV-004 и DV-005.

### 3.2 DV-001 Контекст

* **ID:** DV-001-Context
* **Title:** Границы системы SVS-RVC
* **Viewpoint:** Context
* **Representation:** SVS-RVC — настольное приложение, работающее локально. Внешние акторы: **композитор / продюсер** (импортирует партитуру и текст, выбирает модель, запускает рендер и экспорт), **заказчик / слушатель** (оценивает тембр и разборчивость) и **владелец голоса** (предоставляет RVC-модель и условия её использования). Внешние элементы: файловая система, аудиоустройство, локальная библиотека моделей; сеть не требуется.

  Сервисы: импорт партитуры и лирики, привязка слогов, выбор и проверка модели, офлайн-рендер, real-time-мониторинг, экспорт и сохранение проекта.

* **SRS Requirements:** REQ-FUNC-001, REQ-FUNC-003, REQ-FUNC-004, REQ-SEC-001
* **Decision:** ADR-001
* **More Information:** Границы не включают обучение моделей и облачные вычисления; библиотека моделей принадлежит пользователю.

### 3.3 DV-002 Композиция

* **ID:** DV-002-Composition
* **Title:** Компонентная декомпозиция
* **Viewpoint:** Composition
* **Representation:** Система разделена на четыре слоя: представление (Qt 6 Widgets), приложение (контроллеры), домен (алгоритмы и сущности) и инфраструктура (файлы, ONNX Runtime, аудио, настройки). Домен не зависит от GUI, инфраструктурные библиотеки заменяемы.

  | Компонент | Ответственность | Требования |
  |-----------|-----------------|------------|
  | `MainWindow` | Окно: партитура, лирика, инспектор голоса, транспорт, меню | REQ-FUNC-001, REQ-FUNC-004 |
  | `ProjectController` | Координация проекта, импорт, сохранение, состояние | REQ-FUNC-001, REQ-FUNC-005 |
  | `MidiImporter` | Разбор SMF 0/1: ноты, длительности, темп | REQ-FUNC-001 |
  | `LyricsAligner` | Привязка слогов к нотам, предупреждение при несовпадении | REQ-FUNC-001 |
  | `SvsEngine` | Синтез вокального сигнала по партитуре и фонемам | REQ-FUNC-003 |
  | `RvcConverter` | Перенос тембра: ContentVec/HuBERT, индексный поиск, генератор | REQ-FUNC-002, REQ-FUNC-003 |
  | `AudioExporter` | Запись WAV/FLAC, атомарное сохранение | REQ-FUNC-004, REQ-FUNC-005 |
  | `ModelRepository` | Сканирование библиотеки, манифесты, проверка хешей | REQ-FUNC-002 |
  | `OnnxModelLoader` | Загрузка ONNX-сессий, выбор execution provider | ADR-001 |
  | `AudioDevice` | Вывод real-time-аудио, буферизация, обработка underrun | REQ-PERF-001 |

* **SRS Requirements:** REQ-FUNC-001, REQ-FUNC-002, REQ-FUNC-003, REQ-FUNC-004, REQ-FUNC-005
* **Decision:** ADR-001
* **More Information:** `SvsEngine` и `RvcConverter` скрыты за интерфейсами, поэтому модель или движок можно заменить без изменения UI.

### 3.4 DV-003 Интерфейс

* **ID:** DV-003-Interface
* **Title:** Контракты компонентов и форматы данных
* **Viewpoint:** Interface
* **Representation:** Внешние контракты — C++-интерфейсы, форматы файлов и события UI. Все интерфейсы возвращают результат через `Result<T, Error>` и не бросают исключения через границы слоёв.

  ```cpp
  struct AlignedScore;   // ноты, слоги, темп, язык
  struct AudioBuffer;    // сэмплы, частота, каналы, разрядность
  struct ModelInfo;      // id, name, version, sampleRate, files, sha256
  struct RenderSettings; // модель, параметры F0, качество
  struct ExportSettings; // путь, формат, частота, разрядность, каналы

  class IMidiImporter {
  public:
      virtual Result<Score, ImportError> import(const std::filesystem::path& path) = 0;
  };

  class ILyricsAligner {
  public:
      virtual Result<AlignedScore, AlignmentError> align(const Lyrics&, const Score&) = 0;
  };

  class IModelRepository {
  public:
      virtual std::vector<ModelInfo> scan() = 0;
      virtual Result<ModelInfo, ModelError> validate(const std::string& modelId) = 0;
  };

  class ISynthesisPipeline {
  public:
      virtual Result<AudioBuffer, RenderError> render(const AlignedScore&, const ModelInfo&,
                                                      const RenderSettings&, IProgress&) = 0;
  };

  class IAudioExporter {
  public:
      virtual Result<void, ExportError> exportAudio(const AudioBuffer&,
          const std::filesystem::path&, const ExportSettings&) = 0;
  };

  class IRealtimeMonitor {
  public:
      virtual Result<void, AudioError> start(const AlignedScore&, const ModelInfo&,
                                             const RenderSettings&) = 0;
      virtual void stop() = 0;
  };
  ```

  Ошибки: `E_MIDI_*`, `E_ALIGN_*`, `E_MODEL_*`, `E_RENDER_*`, `E_EXPORT_*`, `E_AUDIO_*`.

  **Форматы данных.**

  | Формат | Назначение | Обязательные поля / параметры |
  |--------|------------|-------------------------------|
  | `.svsproj` | Проект | `version`, `midiPath`, `lyrics`, `language`, `modelId`, `renderSettings`, `exportSettings` |
  | `model.json` | Манифест RVC-модели | `id`, `name`, `version`, `sampleRate`, `f0`, `onnxFiles`, `indexFile`, `license`, `sha256` |
  | WAV / FLAC | Экспорт | PCM 16/24 bit, 44.1/48 kHz, mono/stereo |
  | MIDI | Импорт | SMF 0/1, ноты, длительности, темп |

  **Инварианты:**

  * приложение не выполняет сетевых запросов для синтеза, хранения и экспорта (REQ-SEC-001);
  * рендер запрещён, если модель не прошла `validate` (REQ-FUNC-002);
  * частоты дискретизации модели, F0-контура и выходного буфера согласованы;
  * экспорт идёт во временный файл с последующим переименованием;
  * пути и имена файлов обрабатываются в UTF-8, включая кириллицу (REQ-FUNC-005);
  * real-time-буфер — 128–256 сэмплов, целевая задержка — не более 250 мс (REQ-PERF-001).

* **SRS Requirements:** REQ-FUNC-001, REQ-FUNC-002, REQ-FUNC-003, REQ-FUNC-004, REQ-FUNC-005, REQ-PERF-001, REQ-SEC-001
* **Decision:** ADR-001
* **More Information:** Формат `.svsproj` версионируется; неизвестные поля сохраняются для обратной совместимости. Хеш в манифесте модели выявляет повреждение до загрузки в ONNX Runtime.

### 3.5 DV-004 Взаимодействие

* **ID:** DV-004-Interaction
* **Title:** Сценарии выполнения
* **Viewpoint:** Interaction
* **Representation:**

  **Счастливый путь: импорт → рендер → прослушивание → экспорт.**

  1. Композитор открывает проект или импортирует MIDI и лирику.
  2. `MidiImporter` разбирает партитуру, `LyricsAligner` привязывает слоги к нотам.
  3. Композитор выбирает RVC-модель; `ModelRepository` проверяет манифест, хеш и совместимость.
  4. `RenderController` запускает `SynthesisPipeline`: SVS-этап формирует сигнал, RVC-этап переносит тембр, постобработка убирает артефакты.
  5. Результат прослушивается в приложении, `AudioExporter` сохраняет WAV/FLAC в выбранный каталог.

  **Пути отказа.**

  | Сценарий | Триггер | Поведение системы | Требования |
  |----------|---------|-------------------|------------|
  | Несовпадение слогов и нот | Количество слогов ≠ количество нот | Предупреждение с автоматическим распределением или ручной правкой; рендер не блокируется | REQ-FUNC-001 |
  | Повреждённая или несовместимая модель | Ошибка хеша, ONNX-файла, частоты или входов | Рендер запрещён, показывается сообщение и список валидных моделей | REQ-FUNC-002 |
  | Отмена или совпадение имени при экспорте | Закрыт диалог; файл уже существует | Временный файл удаляется; при совпадении — запрос на перезапись | REQ-FUNC-005 |
  | Нет аудиоустройства | Real-time-режим недоступен | Сообщение и предложение перейти в офлайн-рендер | REQ-PERF-001 |
  | Underrun в real-time | Не хватает времени на буфер | Буфер увеличивается до 256 сэмплов, качество preview снижается, событие пишется в лог | REQ-PERF-001 |

* **SRS Requirements:** REQ-FUNC-001 … REQ-FUNC-005, REQ-PERF-001, REQ-REL-001
* **Decision:** ADR-001
* **More Information:** Все длительные операции выполняются в фоновом потоке с прогрессом и отменой; UI-поток не блокируется.

### 3.6 DV-005 Динамика состояний

* **ID:** DV-005-StateDynamics
* **Title:** Состояния приложения, рендера, модели и real-time
* **Viewpoint:** State Dynamics
* **Representation:**

  **Состояния приложения и проекта.**

  | Состояние | Триггер | Следующее состояние / действие |
  |-----------|---------|--------------------------------|
  | `NoProject` | запуск приложения | `ProjectLoaded` после открытия или импорта |
  | `ProjectLoaded` | загружены MIDI и лирика | редактирование, выбор модели |
  | `ModelSelected` | модель прошла проверку | `Rendering` по кнопке «Рендер» |
  | `Rendering` | запущен синтез | `Rendered` или `Error` |
  | `Rendered` | синтез завершён | прослушивание, `Exporting` |
  | `Exporting` | выбран путь и формат | `Exported` или `Error` |
  | `Exported` | файл записан | `Rendered` (продолжить) |
  | `Error` | сбой или отмена | `ProjectLoaded` после исправления |

  **Состояния модели:** `Available` → `Validating` (чтение манифеста и хеша) → `Valid` | `Corrupt` | `Incompatible`. Выбор и рендер разрешены только в `Valid`; в остальных состояниях показывается сообщение, выбор заблокирован.

  **Состояния real-time:** `Stopped` → `Starting` (открытие устройства) → `Running` | `Failed`; в `Running` возможен `Underrun` (увеличить буфер, снизить качество preview, вернуться в `Running`), остановка — `Stopping` → `Stopped`.

* **SRS Requirements:** REQ-FUNC-001, REQ-FUNC-002, REQ-FUNC-003, REQ-FUNC-004, REQ-FUNC-005, REQ-PERF-001, REQ-REL-001
* **Decision:** ADR-001
* **More Information:** `Rendering` не блокирует закрытие приложения: при выходе пользователь подтверждает отмену рендера. Отмена освобождает ресурсы ONNX Runtime и удаляет временные файлы.

### 3.7 DV-006 Зависимости

* **ID:** DV-006-Dependency
* **Title:** Направленные зависимости компонентов
* **Viewpoint:** Dependency
* **Representation:**

  Цепочка зависимостей: UI → Application → Domain → Infrastructure → внешние библиотеки; домен использует интерфейсы инфраструктуры.

  Правила зависимостей:

  * UI зависит только от контроллеров приложения, не от ONNX Runtime и файловой системы напрямую;
  * домен не зависит от Qt Widgets; допустимы только Qt Core и стандартная библиотека C++;
  * инфраструктура реализует интерфейсы, объявленные в домене/приложении, внешние библиотеки изолированы в инфраструктурном слое;
  * `ModelRepository` — единственный владелец метаданных моделей, `SettingsStore` — пользовательских настроек;
  * циклических зависимостей нет; состояние проекта хранится в `.svsproj`, модели — в локальной библиотеке.

* **SRS Requirements:** REQ-FUNC-002, REQ-FUNC-003, REQ-SEC-001, REQ-PERF-001
* **Decision:** ADR-001
* **More Information:** Новый формат экспорта затрагивает `AudioExporter`, `ExportSettings` и диалог экспорта; новая RVC-модель не требует изменения кода, если соответствует манифесту.
