# Глоссарий проекта SVS-RVC

Версия 1.0  
Проект «SVS-RVC — студия синтеза поющего голоса»  
Ананьева Т.М., группа 450501  
Ноябрь 2026

> Глоссарий объединяет термины предметной области, проекта и языка UML, которые
> используются в SRS, SDD, ADR и модели динамического поведения. Документ хранится
> отдельно и на него ссылаются остальные артефакты, чтобы определения не дублировались.

| Термин | Определение |
|--------|-------------|
| **SVS** | Singing Voice Synthesis — синтез поющего голоса: построение вокального сигнала по MIDI-партитуре, тексту, фонемам и контуру F0. |
| **RVC** | Retrieval-based Voice Conversion — перенос тембра: преобразование синтезированного голоса к тембру выбранной голосовой модели. |
| **F0** | Основная частота голоса (мелодия), Гц; по контуру F0 задаются высота нот, вибрато, портаменто и глиссандо. |
| **MIDI** | Musical Instrument Digital Interface; в проекте — файл SMF 0/1 с нотами, длительностями и темпом. |
| **SMF** | Standard MIDI File — стандартный формат MIDI-файла; поддерживаются типы 0 и 1. |
| **ONNX** | Open Neural Network Exchange — открытый формат переносимых нейросетевых моделей. |
| **ONNX Runtime** | Кроссплатформенный движок вывода ONNX-моделей; в проекте используется CPU execution provider. |
| **ContentVec / HuBERT** | Модели извлечения лингвистических признаков, применяемые на этапе RVC для сохранения содержания речи и переноса тембра. |
| **DAW** | Digital Audio Workstation — цифровая звуковая станция; целевой потребитель экспортированных WAV/FLAC. |
| **WAV** | Формат аудиофайла без потерь; поддерживаются PCM 16/24 бит, 44,1/48 кГц, моно/стерео. |
| **FLAC** | Формат аудиофайла без потерь с сжатием; параметры аналогичны WAV. |
| **`.svsproj`** | Формат файла проекта (JSON): версия, путь к MIDI, текст лирики, язык, идентификатор модели, настройки рендера и экспорта. |
| **`model.json`** | Манифест RVC-модели: идентификатор, название, версия, частота дискретизации, список ONNX-файлов, индекс, лицензия и SHA-256. |
| **Актёр** | Внешняя по отношению к системе роль (человек, система или устройство), взаимодействующая с системой для достижения цели. В модели: **Композитор / продюсер**, **Владелец голоса**. |
| **Прецедент (вариант использования)** | Описание набора взаимодействий актёра с системой, дающего наблюдаемый результат. Например, **выполнить рендер** или **экспортировать партию**. |
| **Поток событий** | Пошаговое описание хода выполнения прецедента: краткое описание, предусловия, основной поток, альтернативные потоки, потоки ошибок и постусловия. |
| **include** | Связь включения: базовый прецедент обязательно включает поведение другого прецедента. В проекте UC-1 включает UC-2, UC-4 включает UC-3. |
| **extend** | Связь расширения: расширяющий прецедент добавляет необязательное поведение базовому при определённом условии. В проекте UC-9 расширяет UC-5, UC-11 расширяет UC-10. |
| **Диаграмма вариантов использования** | UML-диаграмма границ системы: актёры, прецеденты и связи между ними. В проекте построена как Mermaid `flowchart`, поскольку штатной нотации use case в Mermaid нет. |
| **Диаграмма активности** | UML-диаграмма потока работ: действия, решения, слияния, начальный и конечный узлы. В проекте показывает основной сценарий импорта, рендера и прослушивания. |
| **Диаграмма состояний** | UML-диаграмма конечного автомата: состояния, переходы, события, сторожевые условия и действия. В проекте описаны жизненные циклы проекта, RVC-модели и real-time-мониторинга. |
| **Диаграмма последовательности** | UML-диаграмма взаимодействия: участники, линии жизни, сообщения и комбинированные фрагменты (`alt`, `else`). В проекте показывает импорт, рендер, прослушивание и экспорт. |
| **Real-time-мониторинг** | Режим live-озвучивания партии с задержкой не более 250 мс при буфере 128–256 сэмплов; в MVP перенесён в версию 1.1. |
| **Буфер аудио** | Блок сэмплов, который аудиоустройство обрабатывает за один цикл; в проекте 128–256 сэмплов. |
| **Underrun** | Пропуск дедлайна буфера, при котором аудиопоток не успевает подготовить следующий блок; приводит к щелчкам и требует увеличения буфера или снижения качества preview. |
| **MVP** | Minimum Viable Product — минимально жизнеспособный продукт; в проекте — версия 1.0 с импортом, рендером, экспортом и сохранением. |
| **SRS** | Software Requirements Specification — спецификация требований к ПО; документ `lab3/srs/srs-svs-rvc.md`. |
| **SDD** | Software Design Description — описание дизайна ПО; документ `lab4/sdd/project-sdd.md`, версия 0.2. |
| **ADR** | Architectural Decision Record — протокол архитектурного решения; в проекте ADR-001 о локальном конвейере SVS → RVC на ONNX Runtime. |
| **REQ / BR** | Идентификаторы требований: REQ — требование SRS, BR — бизнес-требование; используются для трассировки модели на требования. |
