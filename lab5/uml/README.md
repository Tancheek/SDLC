> или в Mermaid CLI.

## Как рендерить

Диаграммы написаны на Mermaid 11. Варианты рендеринга:

* **GitHub / GitLab** — файлы `.mmd` отображаются в Markdown-блоке ```` ```mermaid ````;
  для этого содержимое файла без front matter вставляется в блок.
* **Mermaid CLI**:
  ```text
  mmdc -i use-case-diagram.mmd -o use-case-diagram.svg
  mmdc -i activity-diagram.mmd -o activity-diagram.svg
  mmdc -i state-diagram.mmd -o state-diagram.svg
  mmdc -i sequence-diagram.mmd -o sequence-diagram.svg
  ```
* **VS Code** — расширения «Mermaid Preview» или «Markdown Preview Mermaid Support».
* **Отчёт** — изображения в `rendered/` получены из тех же `.mmd`; для компактной
  вёрстки диаграмм вариантов использования и активности использован плагин
  `@mermaid-js/layout-elk` (`flowchart-elk`). Исходники при этом остаются
  стандартными `flowchart` и рендерятся на GitHub без плагина.

Все диаграммы начинаются с директивы `%%{init}%%`, которая задаёт белый фон и
тёмные линии, чтобы модель читалась в светлой и тёмной теме GitHub.

## Как построена модель

1. **Границы и актёры** взяты из SRS v0.2 (разделы 2.2–2.4) и SDD DV-001:
   композитор/продюсер и владелец голоса; заказчик/слушатель — стейкхолдер.
2. **Прецеденты** выведены из функций продукта (SRS, раздел 2.2) и требований
   REQ-FUNC-001…005, REQ-PERF-001, REQ-SEC-001. Связи `include`/`extend`
   отражают обязательные и необязательные фрагменты поведения.
3. **Диаграмма активности** показывает упрощённый линейный сценарий
   «импорт → проверка модели → рендер → прослушивание/экспорт»; пути отказа
   описаны в спецификации прецедентов.
4. **Диаграмма состояний** описывает жизненный цикл проекта и рендера:
   `NoProject → ProjectLoaded → Rendering → Rendered → Exported`, ветвь `Error`.
   Состояния RVC-модели и real-time-мониторинга подробно описаны в SDD DV-005
   и в диаграмму не включены, чтобы сохранить простоту.
5. **Диаграмма последовательности** связывает сценарии с компонентами SDD
   DV-002 и контрактами DV-003: `MainWindow`, `ProjectController`,
   `SynthesisPipeline`, `AudioExporter` (и актёр «Композитор»).

Для всех линейных диаграмм задан `"curve": "step"`, поэтому связи идут
перпендикулярно, без дуг и bezier-кривых. Диаграмма вариантов использования
для отчёта дополнительно отрендерена с плагином ELK; исходники остаются
стандартными `flowchart` и рендерятся на GitHub без плагина.
