# Спецификация вариантов использования SVS-RVC

Версия 1.0  
Проект «SVS-RVC — студия синтеза поющего голоса»  
Ананьева Т.М., группа 450501  
Ноябрь 2026

> Документ дополняет диаграмму `use-case-diagram.mmd`. Модель упрощена:
> два актёра и семь прецедентов. Для каждого прецедента приведены пояснение,
> предусловия, основной и альтернативные потоки, постусловия и ссылки на SRS.

## 1. Актёры

| Актёр | Описание роли |
|-------|---------------|
| **Композитор / продюсер** | Импортирует MIDI и лирику, выбирает RVC-модель, запускает рендер, прослушивает результат, экспортирует WAV/FLAC и сохраняет проект. |
| **Владелец голоса** | Предоставляет RVC-модель и управляет локальной библиотекой моделей. |

> **Заказчик / слушатель** — стейкхолдер, а не актёр приложения: он участвует в
> прослушивании и оценке результата, но не выполняет действий в системе.

* `UC-4 Прослушать результат` → **extend** → `UC-3 Выполнить рендер` — прослушивание является необязательным продолжением рендера.

## 3. Описания прецедентов

### UC-1 — Импортировать MIDI и лирику

* **Пояснение.** Композитор выбирает MIDI-файл и файл лирики; система разбирает партитуру, привязывает слоги к нотам и отображает результат.
* **Предусловия.** Приложение запущено; MIDI имеет формат SMF 0/1; текст сохранён в UTF-8.
* **Основной поток:**
  1. Композитор выбирает MIDI-файл и файл лирики.
  2. `MidiImporter` извлекает ноты, длительности и темп.
  3. `LyricsAligner` привязывает слоги к нотам.
  4. `MainWindow` отображает партитуру и лирику.
* **Альтернативные потоки:** пустой или повреждённый MIDI → сообщение об ошибке; несовпадение количества слогов и нот → предупреждение и автоматическое распределение слогов.
* **Постусловия.** Проект создан или обновлён; партитура и слоги отображены.
* **Требования.** REQ-FUNC-001.

### UC-2 — Выбрать RVC-модель

* **Пояснение.** Система выбирает RVC-модель из локальной библиотеки и проверяет её перед рендером.
* **Предусловия.** Проект загружен; библиотека моделей доступна.
* **Основной поток:**
  1. Композитор выбирает модель из списка.
  2. `ModelRepository` читает `model.json` и проверяет SHA-256.
  3. Система проверяет частоту дискретизации и совместимость.
  4. Модель получает состояние `Valid`.
* **Альтернативные потоки:** повреждённая модель → `Corrupt`; несовместимая модель → `Incompatible`; выбор и рендер блокируются.
* **Постусловия.** Модель выбрана и валидна либо показано сообщение об ошибке.
* **Требования.** REQ-FUNC-002.

### UC-3 — Выполнить рендер

* **Пояснение.** Система синтезирует вокальную партию по партитуре и тексту с переносом тембра выбранной RVC-модели.
* **Предусловия.** Есть `AlignedScore`; выбрана валидная модель; заданы настройки рендера.
* **Основной поток:**
  1. Композитор нажимает «Рендер».
  2. `ProjectController` запускает `SynthesisPipeline`.
  3. Система формирует фонемы и контур F0.
  4. `SvsEngine` синтезирует голос, `RvcConverter` переносит тембр, `AudioPostProcessor` выполняет постобработку.
  5. Результат `AudioBuffer` доступен для прослушивания и экспорта.
* **Альтернативные потоки:** отмена или ошибка рендера → сообщение, временные файлы удаляются.
* **Постусловия.** Результат готов либо показана ошибка.
* **Требования.** REQ-FUNC-003.

### UC-4 — Прослушать результат

* **Пояснение.** Композитор или слушатель воспроизводит готовую партию.
* **Предусловия.** Есть готовый результат рендера.
* **Основной поток:**
  1. Пользователь нажимает «Прослушать».
  2. Система выводит аудио через `AudioDevice`.
  3. Воспроизведение останавливается пользователем или завершается автоматически.
* **Альтернативные потоки:** нет аудиоустройства → сообщение и предложение продолжить без прослушивания.
* **Постусловия.** Воспроизведение завершено; проект не изменён.
* **Требования.** REQ-FUNC-003, REQ-REL-001.

### UC-5 — Экспортировать WAV/FLAC

* **Пояснение.** Система сохраняет готовую партию в выбранный каталог в формате WAV или FLAC.
* **Предусловия.** Есть готовый результат рендера; выбран каталог и формат.
* **Основной поток:**
  1. Композитор нажимает «Экспорт» и выбирает путь и параметры.
  2. При совпадении имени система запрашивает подтверждение перезаписи.
  3. `AudioExporter` записывает временный файл и переименовывает его.
  4. Система показывает путь к файлу.
* **Альтернативные потоки:** отмена → файл не создаётся; ошибка ввода-вывода → сообщение, существующий файл не изменяется.
* **Постусловия.** Файл сохранён либо показана ошибка.
* **Требования.** REQ-FUNC-004, REQ-FUNC-005.

### UC-6 — Сохранить проект

* **Пояснение.** Система сохраняет проект в формате `.svsproj`, чтобы продолжить работу позже.
* **Предусловия.** Проект загружен или создан.
* **Основной поток:**
  1. Композитор выбирает «Сохранить».
  2. `ProjectSerializer` записывает версию, путь к MIDI, лирику, модель и настройки.
  3. Запись выполняется атомарно.
* **Альтернативные потоки:** ошибка записи → сообщение, исходный файл не изменяется.
* **Постусловия.** Проект сохранён.
* **Требования.** REQ-FUNC-001, REQ-FUNC-005.

### UC-7 — Управлять библиотекой моделей

* **Пояснение.** Владелец голоса добавляет, удаляет и проверяет RVC-модели в локальной библиотеке.
* **Предусловия.** Приложение запущено; каталог библиотеки доступен.
* **Основной поток:**
  1. Владелец открывает менеджер моделей.
  2. `ModelRepository` сканирует каталог и читает манифесты.
  3. Система показывает список моделей и их статусы.
  4. Владелец добавляет или удаляет модель.
* **Альтернативные потоки:** повреждённый манифест → модель помечается `Corrupt`.
* **Постусловия.** Библиотека обновлена.
* **Требования.** REQ-FUNC-002.
